# AI 数字人直播助手（ai-live-local）

目标是做一个全本地运行的 Windows 桌面应用：用主播自己的真人视频和声音，生成会实时回答弹幕的数字人，把画面送进抖音直播伴侣开播。

> **当前结论（2026-11-25）：测试过的两种口型驱动方法，在本项目的目标条件下都不可行。** 项目没有可用版本，也没有安装包。下面是两种方法的测试情况和不可行的原因。

## 目标条件

一种口型方法要同时满足下面四条才算可行：

| 条件 | 要求 |
|---|---|
| 硬件 | 一张 RTX 3060 12G，大模型、语音合成、口型驱动全部在本机运行 |
| 输入 | 主播自己拍的真人视频（竖屏，半身或全身），不是单张照片 |
| 实时 | 画面 25 fps 不卡顿，弹幕到达后几秒内开口 |
| 画质 | 嘴部周围不能发糊，观众不能一眼看出是合成的 |

## 测试环境

- 测试机：RTX 3080 Ti 12G，Xeon Gold 6248（6 核），32G 内存，Windows Server 2022。**不是目标机。**
- 3060 的算力约为 3080 Ti 的一半。下文"折算到 3060"都按这个比例估算，没有 3060 实机数据。
- 素材：一段 1080x1920 的真人说话视频（12.5 秒，人脸约 460x560 像素），克隆音色的中文语音。

## 方法一：MuseTalk 1.5

**做法**：只重新生成嘴和下巴一带，贴回原视频帧，画面其余部分是原始像素。模型输出 256x256 的人脸。

这是项目一直采用的方案，实时流程（`core/live.py`）已经完整跑通：弹幕到达、大模型流式生成回复、克隆语音流式合成、口型按音频块增量生成、播放端按 25 fps 时钟出画面。

**实测**（大模型、语音合成、口型三者同时运行，5 条弹幕，共 4 次运行）：

| 指标 | 结果 |
|---|---|
| 口型生成速度（显卡部分，单独运行） | 约 23 毫秒/帧，约 43 fps |
| 折算到 3060 | 约 21 fps，低于 25 fps |
| 平均响应延迟（弹幕到达到开口） | 1.03 到 1.13 秒 |
| 说话中卡顿 | 4 次运行里有 3 次，在第一条回复卡 0.20 到 0.36 秒 |
| 显存峰值（三个模型合计） | 约 9.5G |

**为改善嘴部清晰度做过的处理**，都在 `engines/lipsync.py` 和 `engines/enhance.py`：

1. 融合范围从整个下半脸收窄到嘴和下巴。
2. 嘴部用小型超分网络（Real-ESRGAN 紧凑版）放大，每帧约 3 毫秒。
3. 把原视频的皮肤纹理（毛孔、胡茬）叠回生成区域。
4. 嘴唇区域单独锐化（这里不能叠纹理，原先没有任何增强）。
5. 超分结果一次缩放到人脸框大小，去掉中间固定 512x512 的那次重采样。

前三项把下半脸清晰度从原画面的 62% 提到 94%（这个指标包含叠回的皮肤纹理，嘴唇本身没有这么高）。后两项只带来小幅改善，速度不变。

**不可行的原因**：

- **嘴部发软，肉眼可见**。模型只输出 256x256，测试素材的人脸约 460x560，要放大约两倍。嘴唇边缘和牙齿的细节在模型输出里就不存在，后处理补不回来。上面五项处理做完后，嘴部仍然偏软。
- **3060 上速度不够**。折算约 21 fps，而且这是口型单独运行的数字，和语音合成同时运行时还会更慢。

## 方法二：SoulX-FlashHead Lite

**做法**：扩散模型，根据一张人像图片和音频生成整个头部画面，包括头部转动、表情和眨眼。输出 512x512，25 fps，每次生成 24 帧，4 步采样。

**实测**（只运行这一个模型，没有同时运行大模型和语音合成；输入是测试视频的第一帧和 16 秒克隆语音；共运行 2 次）：

| 指标 | 结果 |
|---|---|
| 生成速度 | 每 24 帧约 0.53 秒，约 45 fps |
| 折算到 3060 | 约 22 fps，低于 25 fps |
| 显存峰值 | 6.2G 到 6.5G |
| 启动时的编译时间 | 首次约 7 分 40 秒，再次启动约 1 分 36 秒 |
| 输出 | 512x512 的头部画面 |

画面上，嘴唇轮廓和牙齿比 MuseTalk 清楚，人物长相前后一致；皮肤在生成过程中逐渐变光滑，有磨皮感。

**不可行的原因**：

- **不能用视频做输入**。它只接受单张图片，输出是裁出来的 512x512 头部，没有贴回原画面的步骤。主播视频里的身体、手势、背景都用不上，和"用主播自己的视频"这个前提冲突。
- **12G 显存没有余量**。它单独占 6.2G 到 6.5G，加上语音合成约 2G 和本地大模型约 3G，合计约 11.5G，没有实测过三者同时运行。MuseTalk 的经验是显存一旦溢出，速度会下降几十倍。
- **3060 上速度不够**。单独运行折算约 22 fps，和语音合成同时运行时还会更慢。
- **响应变慢**。按 24 帧一块生成，要先攒够约 1 秒音频才能出第一块画面。
- **许可有限制**。Lite 版使用的 VAE 是 Open-RAIL-M 许可，带使用限制。

它在 Windows 上不能直接安装：依赖的多显卡库只支持 Linux。测试时用 `scripts/flashhead_stubs` 里的单显卡替身模块代替，没有修改它的代码。

## 对比

| | MuseTalk 1.5 | SoulX-FlashHead Lite |
|---|---|---|
| 输入 | 真人视频 | 单张图片 |
| 输出 | 嘴部贴回原视频，分辨率不变 | 512x512 头部 |
| 模型输出分辨率 | 256x256 | 512x512 |
| 3080 Ti 上的速度（单独运行） | 约 43 fps | 约 45 fps |
| 折算到 3060 | 约 21 fps | 约 22 fps |
| 显存（单独运行） | 约 3.3G | 6.2G 到 6.5G |
| 嘴部清晰度 | 发软 | 清楚 |
| 卡在哪 | 画质，3060 上的速度 | 输入形式，显存，3060 上的速度 |

## 结论

两种方法都不可行：

- **MuseTalk** 能用主播的视频、能实时、显存放得下，但嘴部画质达不到"看不出是合成的"，这是模型分辨率决定的，后处理已经做到头。
- **SoulX-FlashHead Lite** 嘴部清楚，但只能从单张图片生成头部画面，用不了主播的视频，12G 显存也没有余量。
- 两者折算到 3060 都低于 25 fps。

在 RTX 3060 12G 上同时满足"用真人视频、全本地、实时、嘴部清晰"，目前测过的方法里没有能做到的。

另一个候选 Ditto 只读过代码，没有实测：它支持视频输入并贴回原画面，输出 512x512，但官方只在 A100 上测试过，没有给出帧率数字。

## 已经跑通的部分

和口型方法无关，这些环节的实测结果仍然有效：

- **大模型**：Qwen3-4B（Q4_K_M 量化，llama.cpp），第一句回复 0.1 到 0.2 秒。
- **声音克隆**：GPT-SoVITS v2ProPlus，流式合成，首块约 0.6 秒出声。
- **实时调度**：时钟驱动的播放端，语音和口型增量生成，弹幕到开口约 1 秒。

## 复现

脚本都针对开发服务器的目录结构（`C:\ai_live`）编写。

```powershell
# 安装环境和模型
powershell -ExecutionPolicy Bypass -File scripts\setup_envs.ps1                  # MuseTalk、GPT-SoVITS、大模型
powershell -ExecutionPolicy Bypass -File scripts\setup_envs.ps1 -Only flashhead  # SoulX-FlashHead Lite

# 方法一：实时流程（在项目根目录下，用 sovits 环境的 python）
python -m core.live --danmaku examples\danmaku_ai.txt --persona_file examples\persona_ai_host.txt `
    --avatar <MuseTalk 预处理好的素材目录> --ref_audio ref.wav --ref_text "参考音频的文本" `
    --out live.mp4 --deterministic --interval 20

# 方法二：单张图片加音频
powershell -ExecutionPolicy Bypass -File scripts\bench_flashhead.ps1 -Image face.png -Audio speech16k.wav -Out out.mp4
```
